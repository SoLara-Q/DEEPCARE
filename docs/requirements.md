# DeepCare 项目需求拆解

## 1. 来源与范围

本文件根据实验任务书中“项目启动、需求分析与数据库设计实践”的要求整理。任务书明确要求初始化 SpringBoot3 后端项目，拆解 DeepCare 家庭健康助手的七大业务模块，完成 E-R 图和数据表设计，使用 MyBatis-Plus 生成持久层代码，并输出需求文档和数据库设计文档。

任务书中的实验报告填写项、评分标准、实验日期和教师评语属于课程记录内容，不属于系统功能需求；本项目只实现其中的工程建设要求。

## 2. 项目目标

DeepCare 面向家庭健康管理，统一保存用户身份、健康档案、日常生理指标、问诊过程、药品信息、处方记录和 AI 模型配置，为后续大模型问答、健康趋势分析和用药提醒提供数据基础。

## 3. 七大业务模块

| 模块 | 核心职责 | 关键实体 |
| --- | --- | --- |
| 用户账号 | 注册身份、联系方式、启停状态和逻辑删除 | `user_account` |
| 健康档案 | 保存用户的基础健康资料、过敏史和慢性病史 | `health_profile` |
| 生理指标 | 保存体温、心率、血压和血氧等测量结果 | `vital_sign_record` |
| 问诊记录 | 保存用户问题、AI 摘要、诊断建议和处理状态 | `consultation_record` |
| 药品库 | 管理药品名称、剂型、用量、库存和风险提示 | `medicine` |
| 处方记录 | 关联用户、问诊和药品，保存服法与疗程 | `prescription_record` |
| AI 模型 | 管理模型供应商、模型名、地址和启用状态 | `ai_model_config` |

## 4. 关系与约束

- 一个用户对应至多一份健康档案。
- 一个用户可以拥有多条生理指标记录和问诊记录。
- 一条问诊记录可以关联多条处方记录；处方中的药品来自药品库。
- 用户账号是业务数据的主主体，健康档案、生理指标、问诊记录和处方记录通过 `user_id` 外键关联。
- 所有主键使用自增 BIGINT；账号使用逻辑删除字段 `deleted`；重要时间字段使用数据库默认时间。
- 账号用户名唯一；生理指标按用户和测量时间建立联合索引；药品名称建立检索索引。

## 5. 非功能要求

- 数据库连接通过环境变量覆盖，禁止把真实密钥写入仓库。
- API 返回统一结构，便于后续接入前端。
- Spring AI 当前通过 `spring-ai` Maven profile 接入 Client Chat 依赖并保留模型配置表；具体模型供应商通过 provider starter 和环境变量扩展。
- 医疗信息属于敏感数据，后续正式开发需要补充认证、权限、审计、脱敏和免责声明。

## 6. 后续迭代建议

1. 为账号模块加入密码哈希、登录会话和权限控制。
2. 为生理指标增加范围校验、趋势查询和异常提醒。
3. 在问诊模块接入 Spring AI ChatClient，并保存模型调用审计信息。
4. 增加分页、条件查询、参数校验和统一异常处理。
5. 为处方和药品增加库存扣减、禁忌校验及人工确认流程。
